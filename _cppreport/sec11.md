本课题要求在给定的《帝国时代》实时战略游戏引擎之上，实现我方（玩家 0）的完整 AI 决策程序，使其在无人干预的条件下独立完成一整局对战。

**一、课题所解决的问题**

1．**全流程决策自动化。** AI 必须自主完成「资源采集 → 经济发展 → 时代升级 → 军事生产 → 三波防守 → 反攻」的完整流程，并在 30 分钟（45000 帧，25 帧/秒）的游戏时限内结束战斗，全程不接受任何人工操作。

2．**非常规胜利条件带来的核心矛盾。** 本课题的胜负判定与常规即时战略游戏不同：

- 胜利 = 祭司成功**感化**敌方**攻城武器厂**（`BUILDING_SIEGE`）；
- 失败 = 祭司阵亡 / 城镇中心被摧毁 / 超时未达成目标。

由于祭司的感化射程仅有 12 格，而敌方武器厂位于基地纵深，因此整局的实质矛盾是：**如何在保住祭司的前提下，把它送进敌方武器厂 12 格以内**。这一矛盾直接决定了 AI 的优先级排序——祭司保命高于一切，经济与军事都是为祭司开路的手段。

3．**工程可靠性问题。** 引擎把 AI 放在独立线程中运行，快照数据、指令队列与全局对象表在 AI 线程与主线程之间存在并发访问，若不加防护会随机崩溃；同时引擎对非法指令（如指向不存在单位的移动令）会直接崩溃而非返回错误。因此 AI 侧必须自行实现**快照的零拷贝获取**与**指令提交前的指针体检**。

**二、主要功能**

| 模块 | 主要功能 |
| --- | --- |
| 阶段状态机 | INIT → EARLY_ECONOMY → UPGRADING → DEFENSE_PREP → WAVE1 / WAVE2 / WAVE3 → COUNTERATTACK → VICTORY / DEFEAT |
| 经济管理 | 村民持续生产；食物/木材/黄金/石料四类工作的动态配比与“超目标回撤”；闲置村民兜底分配 |
| 采集健壮性 | 采集卡死检测（空手且非空闲超时）→ 打断 → 拉黑目标资源 → 强制重派 |
| 建造管理 | 房屋、谷仓、仓库、农场、市场、靶场、马厩、箭塔的选址与建造者调度；选址含**可达性预检**与建筑足迹不重叠校验 |
| 科技升级 | 铜器时代升级（含引擎硬前置检查与防卡死重试）、车轮、阔剑、步兵/弓兵护甲链、市场木材与农业科技、箭塔升级 |
| 军事管理 | 兵种配比生产、闲置军事单位回主城待命、反攻集结门槛 |
| 反攻 | 集结 → 推进 → 拆建筑；远程兵“打-拉”（kiting）循环、投石车 standoff、优先攻击敌方箭塔 |
| 祭司专项 | 感化（含前出感化敌方武器厂）> 逃跑保命 > 治疗友军 > 回己方箭塔待命；探路侦察与反攻期护卫 |
| 线程加固 | 主线程代取快照 + `shared_ptr` 零拷贝；帧末唯一提交点，提交前逐条体检指令内的动态指针 |

**三、辅助工具**

- **开发与调试**：Qt Creator 5.9.2、MinGW 32 位 g++ 5.3.0、Git Bash、引擎内置的 `DebugText` 文本日志。
- **自动化验证**：自研 Python 脚本工具链——批量跑局矩阵（多地图 × 多旋转 × 并行度）、结局分类统计（胜 / 祭司死 / 主城毁 / 超时）、机制量提取（心跳分桶统计）、Fisher 精确检验。
- **版本管理**：`.bak_<日期>_<标签>` 时间戳快照 + 命令行 md5 指纹比对（只认内容指纹，不信文件名）。
- **AI 辅助工具**：见 1.5 节。

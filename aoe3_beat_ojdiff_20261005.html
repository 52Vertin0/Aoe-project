6.2 机制：一个闭环自锁

判据（UsrAI.cpp:5188）
  const bool priestAdvStuck = (frame - priestAdvBestFrame > PRIEST_ADV_STUCK_FRAMES);   // 120

脱困分支（:5207）
  if (priestAdvStuck && priestEscapeCd <= 0) {

      B 档（:5241）: tx = priest->DR + sx * side * 4.0 * BL;   ← 同样纯侧移（外加清障）
      priestAdvBestFrame = frame;                              ← 只重置计时，不动 priestAdvBest
  } else {
      正常推进（:5252）: tx = sMemDR - ux2 * 11.0 * BL;        ← 这条【永远进不去】

自锁环：不靠近（120 帧内未逼近 > 0.5 格） ⇒ 判卡死 ⇒ 脱困只做侧移（不产生朝武器厂的逼近） ⇒ priestAdvBest 永不刷新 ⇒ priestAdvStuck 恒真 ⇒ 永远走脱困分支、永不进入正常推进 ⇒ 原地打转到 30 分钟超时（超时 = 必然输）。

实测落点证实侧移方向与目标方向近乎正交：(54,40) → (53,40) → (53,41)，y 钉在 40 附近， 而武器厂在 y=20（该往南走）⇒ 脱困永远推不进。

⚠ 代码原注释已经防了「基准被自救动作自己带着走」这条路径（铁律 9）， 但漏了同源的第二条：自救动作本身根本不产生进展。两条路都通向同一个活锁 —— 这与本项目已知的「暂停生效了、恢复没生效」「严苛前置条件 + 互斥锁 → 下游本该接力却没接」是同一族缺陷。
全部判据来自引擎日志、不依赖胜负：[PRIEST-ESCAPE A/B]（含落点）、[LC-DBG] dS、 [BEAT] pr@。三者互相独立且完全一致。

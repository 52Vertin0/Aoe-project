4 · 方案 B（fixJ）为何失败 — 以及它挖出的真病根

B 的假设：活锁 = 脱困动作不产生进展 ⇒ 给脱困设总预算，超限后永久改直冲。

实测：机制完全生效（GIVEUP 触发 7 局、闸泄漏 0），但 7 局全部出现四重指纹：

祭司 HumanMove 条数 = 0          ← 整段反攻期一条都没有
pr@ 坐标逐桶冻结                  (58.9,22.5) / (42.0,46.4) … 一字不变
[BEAT] pm 五列全 0                pm f0 ca0 h0 cnt0 o0
[LC-DBG] dS 恒定到局末            37.5 / 25.9 / 48.3 …

⇒ 真病根不是「脱困不产生进展」，而是「理想推进落点 isPassableAt 恒假」： 一条 HumanMove 都发不出去。侧移之所以是唯一发得出的令，正因为它相对当前挪 4 格、几乎总可达。 取消侧移 ＝ 取消唯一的令 ⇒ 祭司反而彻底静止（静止局 2→6）。
教训（已入铁律）：「减少动作」型修法在活锁上没有出路 —— 打转与静止在 dS 上等价。正解是让落点可达。

5 · fixK 改动（纯新增 26 行 / 0 删除）

// :5387 — 理想落点不可达时，沿「祭司 → 理想落点」连线同轴回退取最近可达点
if (!isPassableAt(tx, ty, forestGrid)) {
    const double advOx = priest->DR, advOy = priest->UR;
    for (int k = 1; k <= 4; k++) {
        const double fracD = 1.0 - 0.2 * k;       // 0.8 / 0.6 / 0.4 / 0.2（从最远开始试）
        const double advCx = advOx + (tx - advOx) * fracD;
        const double advCy = advOy + (ty - advOy) * fracD;
        if (isPassableAt(advCx, advCy, forestGrid)) {
            tx = advCx; ty = advCy;
            DebugText(QString("[PRIEST-ADV-DEGRADE ...]"));
            break;
        }
    }
}
  • 同轴 ⇒ dS 减小 = 真进展，刷新卡死计时，逐步逼近
  • 四级全不可达 ⇒ 保持原落点、本帧不发令 ⇒ 仍由侧移档兜底（不会陷入 fixJ 那种静止）
  • 落点可达时行为逐位不变 ⇒ 对现有胜局零影响

6 · 结论与下一步

  • 保留 fixK：机制严格改进（超时＝必输，故 T→W/P 是单向收益），改动面窄、护栏持平、无退化证据。

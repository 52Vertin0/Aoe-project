2. 优化方向（按 ROI 排序）

P0 先把 19485 的形态复现出来 —— 否则一切改动不可验证

本地 108 个祭死局没有一例「临死静默 > 600 帧」，说明触发条件不在本地配置内。候选差异只有两个：

P1 感化引导「超时断路器」（直击 1930 帧静默）

机制假设：canAct = (NowState==IDLE || NowState==WALKING)。祭司起手感化时置 priestMoveCooldown = 150（:1785）， 引导期 NowState 为 WORKING/ATTACKING ⇒ canAct=false ⇒ 下面所有「逃跑 / 治疗 / 待命」分支全被跳过，唯一的出口是 :1696 的 if (!canAct) 块（pBRx <= abortHp 才断引导逃跑）。

19485 里祭司被 6 个单位打了 22 秒仍不撤 ⇒ 该出口没打开。两个可能：(i) danger = (lockers>=2) || (near12>=4) 门槛没达到（25:34:64 只有 3 个同时攻击）； (ii) 血从 >25% 直接被秒 ⇒ 从没进入可撤状态。

改动（一处新增，约 5 行）：用已存在的 priestConvFrame 做硬超时 ——

if (priestConvFrame > -999999 && frame - priestConvFrame > 900) {
    priestMoveCooldown = 0;      // 解除移动锁
    priestConvSN = -1;           // 放弃本次引导，交给下方逃跑闸

验证口径：_priest_deathgap.py 的「祭死局最大静默」应 ≤ 本地基线（≤204 帧）； 次级端点 = 24 局/臂 win%（噪声带 ±14pp ⇒ 只作记账）。

  • :1708 abortHp = danger ? 0.60 : 0.25 ⇒ 反攻期建议固定 0.50~0.60（祭司满血到 25% 在 3 个远程集火下只需几秒）

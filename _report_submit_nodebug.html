2 · 补丁块长什么样

// ...
//   把 ai.h 中 AI::DebugText 的 5 个重载整体屏蔽为无操作 —— 121 处调用全部静默。
//   · 本块必须位于**所有 #include 之后**：放前面会把 ai.h 里的声明一起替换掉 ⇒ 编译错。
//   · 宏体用 `if (0) { (void)(...); }` 而非裸 `((void)0)`：
//     裸写法会把 23 个「只服务打印」的变量变成 unused 警告；
//     if(0) 在 -O2 下整块被删（零运行时开销），但语义上"引用"了实参 ⇒ 不触发 unused。
//   · 外面套 do{}while(0)：调用点存在「单语句 if」的无花括号写法。
// ============================================================================================
#define DebugText(...) do { if (0) { (void)(__VA_ARGS__); } } while (0)

为什么用宏而不是逐处删 121 个调用

  • 风险：121 处里大量是多行链式 .arg()，逐处删容易破坏括号配对，且不可逆。
  • 可证明：宏版是「1 行的改动」，能靠「剥补丁后逐字符相同」把"行为不变"钉死。
  • 必须放最后：DebugText 是 ai.h 里 AI 类的成员函数（5 个重载：std::string / QString / char* / int / double，见 ai.h:66-74）。宏在 #include 之前定义会连声明一起替换掉。本文件最后一个 #include 在第 18 行，宏在第 32 行 ✓。

5 · 两个必须知道的坑

① 语法快检静默 exit=1 ≠ 代码有问题。
本机 PATH 里若没有 32 位工具链目录，g++ 能打印 --version，但一编译就 exit=1 且零输出 —— 因为 cc1plus 子进程找不到配套 DLL。 本次一开始就踩了这个（SRC/NB exit=1、error=0 warning=0、输出 0 字节）。 解法： 
export PATH="/d/360Downloads/Tools/mingw530_32/bin:/d/360Downloads/5.9.2/mingw53_32/bin:$PATH"
② _submit\UsrAI.cpp 仍是 10-06 的 fixM 旧版，本次未动。
现有 _submit\UsrAI.cpp md5 = 055e3668，与当前源码 e5e77387 差 4379 行。 按你的选择（方案 A：只加子目录），本次只新增 _submit\nodebug\，主提交件保持原样。 若以后想让它跟上，跑 python mk_submit.py 即可。

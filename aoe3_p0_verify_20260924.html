1 · 撤回做法（为什么不是逐行删）

P2b 是一整段 24 行的替换（旧 16 行 → 新 40 行）。如果直接在现行版上删，很容易在「删到哪一行结束」上出错，且无法证明 P0 段没被顺手碰过。所以采用回基线重施：

# 1) 留档含 P2b 的版本（可随时复原）
cp UsrAI.cpp _audit/UsrAI.cpp.pp_p0p2b        # 6d2f59cf / 6652
# 2) 回到 P0/P2b 之前的基线
cp UsrAI.cpp.bak_20260924_p0p2b UsrAI.cpp     # 2710f75b / 6622
# 3) 只施 P0（脚本 = apply_p0p2b.py 去掉 P2b 段）
python _audit/apply_p0only.py                 # → 7153039b / 6628
等价性：P0 段与 pp 批逐字相同
因为 P0 的代码是重新施加的、不是被"保留"的，所以不存在"删 P2b 时蹭到 P0"的可能。 双向 diff 佐证：新版 vs 基线 = 4 个 hunk 全落 L966~L1284（P0 区）； 新版 vs pp 版 = 1 个 hunk 落 L3897~3932（P2b 区）。两侧都对上，没有夹带。

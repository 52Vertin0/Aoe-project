4 · 根因链（每层带行号）

① 追敌落点 = 12.0 格，而发感化的判定 = ≤ 12.0 格 ⇒ 零余量

UsrAI.cpp:1803   double stopDist = 12.0;   // 停12格正好进入引擎感化射程(DIS_PRIEST=12)
                 ...
UsrAI.cpp:1525   double bx = pDR + ux * (len - stopDist * BL);   // 落点 = 距目标 stopDist 格
                 ...
UsrAI.cpp:1782   if (cdist <= 12 * BL) {                          // ≤12 才发感化令

落点与判定阈值指向同一个数：祭司被要求停在「恰好等于射程上限」的位置，请求发令的门槛也正好是这个上限。任何一点正向误差（引擎寻路的到位判定误差、目标在移动、calDistance 与引擎 countdistance 的口径差）都会把它推到门槛外面。

② 常量真值回代：DIS_PRIEST 确实是 12，注释没说谎

来源值
config.json:409"DIS_PRIEST": 12
Army.cpp:793（祭司初始化）dis_Attack = DIS_PRIEST;
Army.cpp:385（射程换算）dis = (dis + disAdd) * BLOCKSIDELENGTH;
Core_List.cpp:1732（引擎的射程判定）countdistance(...) <= blooder->getDis_attack()

⇒ 引擎判据是 ≤ 12 格（含边界）。所以「停在 12.0」理论上是达标的，实践中不达标 —— 这正是 12~13 格那一档存在的理由。

③ 同文件同类实现对照：另外 3 处全都留了 1 格余量

用途行号停位余量
追敌感化（priestApproachMove）:1803stopDist = 12.00 格

写这份代码的人自己知道要留余量（另外三条路径都写了 - 1.0），唯独追敌路径写成了裸 12.0。 这是本项目的老毛病「同一语义写多遍、值不一致」（铁律 21/26）在本轮的又一次命中。

④ 第二层：落点被占时的「侧移」会把距离进一步推远

UsrAI.cpp:1527   const double OFF[6] = {0.0, 3.0, -3.0, 6.0, -6.0, 9.0};
UsrAI.cpp:1530   double cx = bx - uy * OFF[o] * BL;   // 垂直于「祭司-敌人」连线方向偏移

侧移是垂直于连线平移，不改变「沿连线方向」的位置 ⇒ 落点到敌人的距离变成 √(12² + off²)：

5 · 次要机制（同向叠加，但不是主因）

反攻期 73% 的时间武器厂还没被发现

[LC-DBG] 的 siegeSN 在反攻期 72.9%（club8n）/ 79.5%（wbase）的采样点为 -1。这段时间祭司没有明确目标，在「找敌人顺便感化」；而 :1811 那条「反攻期 + 已发现武器厂 ⇒ 不主动追敌」的抑制此时不生效（只在剩下 27% 的时间里生效）。

整军在路上 —— 反攻期约 80% 时间离武器厂 ≥ 28 格

顺带发现：选目标用的是「血量最高」而不是「最近」

findConvertTarget（:1465 pickByBlood）四档各档内取血量最高者（同血才取近）。 方阵兵档排第一且血最厚 ⇒ 祭司可能跨十几格去追一个更肉的敌人，途中被消耗。属次要嫌疑，本轮未量化。

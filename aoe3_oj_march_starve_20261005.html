二、败因第三层：行军预算「两遍共享」⇒ 近战整段跳过

反攻段的行军循环写成「先远程、后近战」两遍（pass 0 只跑远程/投石车，pass 1 才跑近战）， 但 外层循环条件里带了 marchCmds < maxMarchCmds，而 marchCmds 是跨两个 pass 累计的同一个计数器：

// 修改前（UsrAI.cpp:5469 附近）
const int maxMarchCmds = readyToAttack ? 8 : (armyCount + 4);
for (int pass = 0; pass < 2 && marchCmds < maxMarchCmds; ++pass) {   // ★ 预算跨两遍共享
    for (auto &a : infoPtr->armies) {
        bool ranged = sortIsRanged(a.Sort);
        if (pass == 0 && !ranged) continue;   // pass 0：只跑远程/投石车
        if (pass == 1 &&  ranged) continue;   // pass 1：才跑近战
        ...
        if (++marchCmds >= maxMarchCmds) break;

几何结论：readyToAttack 为真时上限被硬编码成 8。 只要远程单位数 ≥ 8，pass 0 一个人就把 8 份预算吃光 ⇒ 外层条件 marchCmds < maxMarchCmds 恒假 ⇒ pass 1（近战）一次都不进。

[BEAT] 逐帧行为心跳 —— 让「OJ 上 AI 的行为」与「本地跑」可以按帧对拍

UsrAI.cpp d95a69ad · 7474 行 ｜ 引擎 v3.0.7g 本地 / v3.0.7h OJ ｜ 基线：map.njust -rotate 0 × 3 局 ｜ 2026-10-05
一句话：加了一条每 6 秒一行的 [BEAT] 帧摘要（AI 每帧**看到的输入** + **发出的指令**）， 并写了一个对拍器 _beat_diff.py。关键设计点是按 150 帧分桶采样—— 实测只有这个口径能做到 OJ↔本地 100% 对齐；按帧号对齐最多只有 3.3%~48%。 同时标定了噪声底线：同机同二进制跑两局，结构性差异本来就有 23%（前 9 分钟）/ 76%（全程）， 所以判据不能用"差异率高低"，只能用「阶段机时间戳 Δ」＋「前半程结构性差异率」。

一、加了什么

1.1 [BEAT] 行（每 150 帧一行 + 状态跃迁额外一行）

00:00:041 | 449 | black | 0 |  UsrAI打印：[BEAT f=44850 b=299] st=ATK Frm=22 Idle=0 Walk=1 Work=18 Atk=0 Mil=6 | Fd=0 Wd=0 St=0 Gd=0 | a=7 hop=0 arch=5 oth=1 pr=(sn91168 st1 hp100/100 ccd0) | nEB=6 nEA=4 nMy=6 bbox=(x13.9..84.6,y7.1..86.4) pr@=(13.9,84.6) | ins=12 drop=0 adopt=12 objMv=0 gObj=1357(上帧)
字段含义为什么它重要
f / b真实帧号 / 采样桶号(=f/150)对拍按 b，不按 f（见 §二）
st阶段（INIT/ECO/UPG/PREP/W1/W2/W3/ATK/WIN/LOSE），带 * = 本行是跃迁行「何时进入反攻 ATK」是最强的单一判据
Frm Idle Walk Work Atk村民数 / 各状态分布（口径与 ECO 行完全一致）经济是否真的在转
Mil / a hop arch oth军事总数 / 部队数 / 方阵兵·复合弓兵·其它近战是否被饿死就是看 hop 与 a
pr=(sn.. st.. hp../.. ccd..)祭司 SN / 状态 / 血量 / 转换冷却祭司一死立刻判负；ccd 非 0 = 正在读条
nEB nEA已探明敌建筑数 / 可见敌军数nEB 长期 0 ⇒ 部队根本没出发
bbox=(x..y..) pr@=(..)我方（军队+村民）包围盒 / 祭司坐标，单位=格一眼看出部队在家还是在敌区
ins drop adopt objMv gObj上一帧提交的指令数 / 丢弃数 / 改用当前指针数 / obj 被更新数 / 引擎对象表规模延续 6121/6204 的指令层自证（drop 必须恒 0）

开关：UsrAI.cpp 顶部 #define BEAT_PERIOD 150，改成 0 即整体静音（只留状态跃迁行）。

1.2 配套两个文件（都不进提交件）

  • _beat_run.sh —— 本地跑批：N=3 bash _beat_run.sh ⇒ 产出 beat_1..3.ait（各局 AIText.log 全文，含 [BEAT]）。
  • _beat_diff.py —— 对拍器：python _beat_diff.py <基线> <待比> --label=本地,提交XXXX。

二、采样口径试了三版 —— 这是本次最有价值的一条方法论

采样写法两局对齐率为什么不行
frame - last >= 150（距上次满 150 帧）3.3%各局首帧偏移不同 ⇒ 采样帧集合**完全错开**
frame % 150 == 0（绝对帧网格）48%AI 并非每帧都被调用 —— 实测 frame 会跳号（…300, 600, 750, 900…，450 被跳过）， 哪些网格点被命中各局不同
frame / 150 分桶，每桶首次进入打一行100%AI 一定穿过每个桶 ⇒ 每局恰好 ⌈末帧/150⌉ 个采样点，b 是两侧精确相等的维度

⇒ 通用教训：给"两台机器/两次运行的行为"做逐点对比时，采样点必须由「输入的下标区间」决定， 不能由「真实时钟/帧号」决定。只要采样点会漂，再精确的对比都建立在流沙上。

顺带踩到的两个坑

  • 日志里的 [BEAT] 一行里如果 msg.startswith('[BEAT') 判断，会因行首可能带空格 + UsrAI打印： 前缀而恒 0 —— 用 re.search。
  • 状态名是 W1/W2/W3，解析正则写成 [A-Z]+ 会把 W 后面的数字丢掉 ⇒ 41 行静默解析失败（用 [A-Z][A-Z0-9]*）。

三、噪声底线标定（否则判据一定是错的）

先拿同机、同二进制、同图同朝向跑两局互相对拍，量出"完全同环境"长什么样：

文件 A = beat_1.ait（304 采样行）   B = beat_2.ait（304 采样行）
【1】状态跃迁
  A: INIT@f12 → ECO@f14 → PREP@f5002 → W1@f5005 → ... → W3@f21001 → ATK@f33001
  B: INIT@f12 → ECO@f14 → PREP@f5003 → W1@f5006 → ... → W3@f21001 → ATK@f33003
  Δ:  INIT +0   ECO +0   W1 +1   W3 +0   ATK +2      ← 阶段机是确定性的
  Δ:  UPG -4433  W2 +1430  PREP -1361                  ← 这三个阶段次序会抖（同一波次的不同小分支）

【5】结构性差异
  共同桶 300，有差异 232（77.3%）
  前 9 分钟（b≤90）差 25/91 = 27.5%

⇒ 结论：差异率高是常态，不是证据。后期战场（追击/遭遇/塔血）随机性极大， 两局跑出来的部队数量、敌建筑探明数完全不同。能用的判据只有两条：

  1. (a) 确定性阶段时间戳：INIT/ECO/W1/W3/ATK 的 Δ —— 同环境应 ≤20 帧（实测 2 帧）。
  2. (b) 前半程（b≤90，前 9 分钟）结构性差异率 —— 噪声底线 23%，判据取 ≤35%。

对拍器已把这两条内置成机器判据，并会在输出里打印噪声底线，避免下次又误读 77%。

六、开销与风险

  • 日志量：300 行/局 × ≈250 B ≈ 75 KB；对照 OJ 那份 debug 日志是 783 KB（占 ~10%）。
  • CPU：每 150 帧做一次 ≈30 个单位的遍历 + countAllMilitary()，相对整帧逻辑可忽略。
  • 不改判据：全部字段只读，不写任何 AI 状态；不引用任何引擎新增符号（提交安全）。
  • 可一键关闭：#define BEAT_PERIOD 0。
  • ⚠ 提交件必须 .cpp ＋ .h 成对（.h 这轮没变，但它与 .cpp 是同批产物）。
